# MOMent 데이터베이스 요구사항 분석서

---

## 📋 1단계: 요구사항 정의서 분석

### 1.1 프로젝트 개요
- **프로젝트명**: MOMent (임산부 맞춤 케어 DX 프로젝트)
- **데이터베이스용도**: 임산부, 보호자, 관리자의 데이터를 통합 관리하는 웹앱 백엔드
- **주요 데이터 대상**:
  - 사용자 정보 (임산부, 보호자, 관리자)
  - 임산부 건강 데이터 (상태체크, 일기, 증상)
  - AI 분석 결과 (감정 분석, 추천)
  - 커뮤니티 데이터 (게시글, 댓글)
  - 보호자 미션 데이터
  - 가전 제어 설정 데이터
  - 캘린더/스몰토크 데이터

### 1.2 요구사항 문장 추출
```
1. 사용자는 이메일과 비밀번호로 회원가입 및 로그인한다.
2. 임산부는 임신 시작일을 입력하고, 현재 임신 주차가 자동으로 계산된다.
3. 보호자는 연결코드로 임산부와 연결된다.
4. 임산부는 매일 오늘의 상태체크(기분, 증상, 신체 상태)를 입력한다.
5. 상태체크 입력 시 연결된 보호자에게 자동으로 미션이 생성된다.
6. 임산부는 일기를 작성하고, 작성 시점의 날씨, 온습도 데이터가 자동 저장된다.
7. 일기 텍스트는 AI로 감정 분석되어 감정 결과가 저장된다.
8. 임산부는 현재 임신 주차별 AI 맞춤 추천(식품, 운동, 주의사항, 스트레칭)을 조회한다.
9. 임산부는 공신력 있는 신뢰 정보(영양, 운동, 정신건강, 태아발달, 수면)를 조회한다.
10. 사용자는 임신 시기별로 커뮤니티 게시글을 작성하고 댓글을 달 수 있다.
11. 부부는 스몰토크에서 같은 질문에 답변하고 서로의 답변을 확인한다.
12. 임산부와 보호자는 공유 캘린더에서 병원 검진일, 주요 일정을 관리한다.
13. 임산부의 가전 제어 추천값(온도, 습도, 감정)이 DB에 저장된다.
14. 관리자는 전체 회원, 게시글, 오늘 접속자 통계를 조회한다.
15. 관리자는 회원을 대리접속하고 커뮤니티 게시글/댓글을 삭제할 수 있다.
16. 관리자는 커뮤니티 텍스트를 Kiwi 형태소 분석한다.
```

### 2.2 속성 상세 분석

#### USERS 테이블
```
- user_id (PK): 고유 사용자 ID, AUTO_INCREMENT
- email: 로그인 이메일, UNIQUE, NOT NULL
- password: 해시된 비밀번호, NOT NULL
- name: 사용자 이름
- role: ENUM('PREGNANT', 'GUARDIAN', 'ADMIN') - 사용자 역할
- phone: 전화번호
- created_at: 회원가입 시간
- updated_at: 정보 수정 시간
- deleted_at: 회원탈퇴 시간 (소프트 딜리트용)
```

#### PREGNANCY_INFO 테이블
```
- pregnancy_id (PK): 고유 임신정보 ID
- user_id (FK→USERS): 임산부 사용자 ID, NOT NULL, UNIQUE
- pregnancy_start_date: 임신 시작일, NOT NULL
- baby_nickname: 태아 별명 (기본값: "아기")
- connected_guardian_id (FK→USERS): 연결된 보호자 ID (선택사항)
- created_at: 정보 생성 시간
- updated_at: 정보 수정 시간
```

#### PREGNANCY_STATUS_CHECKS 테이블
```
- status_check_id (PK): 고유 상태체크 ID
- user_id (FK→USERS): 임산부 사용자 ID, NOT NULL
- mood: VARCHAR(50) - 기분 (예: "happy", "tired", "anxious")
- symptoms: JSON - 선택된 증상들 배열
- body_condition: TEXT - 신체 상태 추가 설명
- created_at: 생성 시간 (날짜 기준 1회 저장)
- INDEX(user_id, created_at) - 사용자별 최근 상태체크 조회 최적화
```

#### DIARY_LOGS 테이블
```
- diary_id (PK): 고유 일기 ID
- user_id (FK→USERS): 임산부 사용자 ID, NOT NULL
- content: LONGTEXT - 일기 텍스트 내용
- emotion_emoji: VARCHAR(10) - 선택된 감정 이모지
- diary_date: DATE - 일기 작성 날짜
- created_at: 생성 시간
- updated_at: 수정 시간
- INDEX(user_id, diary_date) - 사용자별 일기 날짜 조회 최적화
```

#### DIARY_SYMPTOMS 테이블
```
- symptom_id (PK): 고유 증상 ID
- diary_id (FK→DIARY_LOGS): 일기 ID, NOT NULL
- felt_temperature: DECIMAL(5,2) - 체감 온도
- felt_humidity: DECIMAL(5,2) - 체감 습도
- weather_api_data: JSON - 날씨 API 응답 전체 저장
- weather_status: VARCHAR(50) - 날씨 상태 (맑음/흐림/비 등)
- created_at: 저장 시간
```

#### AI_ANALYSIS_RESULTS 테이블
```
- analysis_id (PK): 고유 분석 결과 ID
- diary_id (FK→DIARY_LOGS): 일기 ID, NOT NULL, UNIQUE
- emotion_label: VARCHAR(50) - 감정 라벨 (긍정/부정/중립)
- emotion_score: DECIMAL(3,2) - 감정 점수 (0.0 ~ 1.0)
- sentiment_analysis: TEXT - 상세 감정 분석 텍스트
- analyzed_at: 분석 시간
```

#### COMMUNITY_POSTS 테이블
```
- post_id (PK): 고유 게시글 ID
- user_id (FK→USERS): 작성자 사용자 ID, NOT NULL
- title: VARCHAR(255) - 게시글 제목
- content: LONGTEXT - 게시글 내용
- pregnancy_period: ENUM('EARLY', 'MID', 'LATE') - 임신 시기
- like_count: INT (기본값: 0) - 좋아요 수
- created_at: 생성 시간
- updated_at: 수정 시간
- INDEX(pregnancy_period, created_at) - 임신 시기별 조회 최적화
```

#### COMMUNITY_COMMENTS 테이블
```
- comment_id (PK): 고유 댓글 ID
- post_id (FK→COMMUNITY_POSTS): 게시글 ID, NOT NULL
- user_id (FK→USERS): 댓글 작성자 ID, NOT NULL
- content: TEXT - 댓글 내용
- created_at: 생성 시간
- updated_at: 수정 시간
- INDEX(post_id, created_at) - 게시글별 댓글 조회 최적화
```

#### GUARDIAN_MISSIONS 테이블
```
- mission_id (PK): 고유 미션 ID
- status_check_id (FK→PREGNANCY_STATUS_CHECKS): 상태체크 ID, NOT NULL
- guardian_user_id (FK→USERS): 보호자 사용자 ID, NOT NULL
- task_description: TEXT - 미션 설명 (기분/증상에 맞게 자동 생성)
- is_completed: BOOLEAN (기본값: false) - 미션 완료 여부
- completed_at: DATETIME - 미션 완료 시간
- created_at: 미션 생성 시간
- INDEX(guardian_user_id, is_completed) - 보호자별 미완료 미션 조회
```

#### APPLIANCE_SETTINGS 테이블
```
- setting_id (PK): 고유 설정 ID
- user_id (FK→USERS): 임산부 사용자 ID, NOT NULL
- target_temperature: DECIMAL(4,1) - 권장 온도 (℃)
- target_humidity: INT - 권장 습도 (%)
- mood_light_brightness: INT - 무드등 밝기 (0-100%)
- air_purifier_speed: ENUM('LOW', 'MID', 'HIGH') - 공기청정기 풍량
- aircon_fan: ENUM('LOW', 'MID', 'HIGH') - 에어컨 풍량
- created_at: 생성 시간
- updated_at: 수정 시간
- INDEX(user_id, created_at) - 사용자별 최근 설정 조회
```

#### CONNECTION_CODES 테이블
```
- code_id (PK): 고유 연결코드 ID
- pregnant_user_id (FK→USERS): 임산부 사용자 ID, NOT NULL
- guardian_user_id (FK→USERS): 보호자 사용자 ID (연결 후 입력)
- connection_code: VARCHAR(10) - 6자리 고유 연결코드, UNIQUE, NOT NULL
- is_connected: BOOLEAN (기본값: false) - 연결 완료 여부
- created_at: 코드 생성 시간
- connected_at: 실제 연결 시간
- UNIQUE(pregnant_user_id, guardian_user_id) - 임산부-보호자 중복 연결 방지
```

## 🔗 3단계: E-R 다이어그램 분석

### 3.1 엔티티 관계도

```
[USERS] (임산부/보호자/관리자)
  ├─ 1:1 → [PREGNANCY_INFO] (임산부 정보)
  ├─ 1:N → [PREGNANCY_STATUS_CHECKS] (상태체크)
  ├─ 1:N → [DIARY_LOGS] (일기)
  ├─ 1:N → [COMMUNITY_POSTS] (게시글)
  ├─ 1:N → [COMMUNITY_COMMENTS] (댓글)
  ├─ 1:N → [SMALL_TALK_ANSWERS] (스몰토크 답변)
  ├─ 1:N → [SHARED_CALENDAR_EVENTS] (캘린더)
  ├─ 1:N → [APPLIANCE_SETTINGS] (가전 설정)
  ├─ 1:N → [GUARDIAN_MISSIONS] (보호자 미션)
  └─ 1:N → [USER_CARE_PREFERENCES] (설정)

[PREGNANCY_STATUS_CHECKS]
  ├─ 1:1 → [DIARY_LOGS] (같은 날의 일기)
  └─ 1:1 → [GUARDIAN_MISSIONS] (미션 생성)

[DIARY_LOGS]
  ├─ 1:1 → [DIARY_SYMPTOMS] (환경 데이터)
  └─ 1:1 → [AI_ANALYSIS_RESULTS] (감정 분석 결과)

[COMMUNITY_POSTS]
  └─ 1:N → [COMMUNITY_COMMENTS] (댓글)

[SMALL_TALK_TOPICS]
  └─ 1:N → [SMALL_TALK_ANSWERS] (답변)

[WEEKLY_AI_RECOMMENDATIONS]
  └─ N:1 ← [PREGNANCY_INFO] (주차 범위별)

[CONNECTION_CODES]
  ├─ N:1 → [USERS] (임산부)
  └─ N:1 → [USERS] (보호자)
```

### 3.2 카디널리티 (Cardinality) 분석

| 관계 | 카디널리티 | 참여 특성 | 설명 |
|------|-----------|---------|------|
| USERS - PREGNANCY_INFO | 1:1 | 임산부는 필수, PREGNANCY_INFO는 선택 | 임산부만 임신 정보 보유 |
| USERS - PREGNANCY_STATUS_CHECKS | 1:N | 임산부는 필수, 상태체크는 선택 | 하루에 최대 1회 상태체크 |
| USERS - DIARY_LOGS | 1:N | 임산부는 필수, 일기는 선택 | 하루에 1개 이상 일기 가능 |
| USERS - COMMUNITY_POSTS | 1:N | 사용자는 필수, 게시글은 선택 | 게시글 작성은 선택사항 |
| USERS - COMMUNITY_COMMENTS | 1:N | 사용자는 필수, 댓글은 선택 | 댓글 작성은 선택사항 |
| USERS - GUARDIAN_MISSIONS | 1:N | 보호자는 필수, 미션은 선택 | 상태체크 입력 시만 미션 생성 |
| COMMUNITY_POSTS - COMMUNITY_COMMENTS | 1:N | 게시글은 필수, 댓글은 선택 | 게시글 없이 댓글 불가 |
| SMALL_TALK_TOPICS - SMALL_TALK_ANSWERS | 1:N | 질문은 필수, 답변은 선택 | 각 사용자가 답변 |
| PREGNANCY_STATUS_CHECKS - DIARY_LOGS | 1:1 | 상태체크:일기 = 1:0..1 | 상태체크 당일 일기 작성 가능 |
| DIARY_LOGS - DIARY_SYMPTOMS | 1:1 | 일기는 필수, 증상은 필수 | 일기 작성 시 환경 데이터 자동 수집 |
| DIARY_LOGS - AI_ANALYSIS_RESULTS | 1:1 | 일기는 필수, 분석은 필수 | 일기 저장 시 AI 분석 자동 수행 |

### 4.2 정규화 분석 (Normalization)

#### 제1정규형 (1NF) - 원자성
```
✓ 모든 속성은 원자값 (atomic value)
  - 예: symptoms는 JSON 배열로 저장하여 개별 접근 가능
  - 환경 데이터도 별도 테이블로 분리
```

#### 제2정규형 (2NF) - 부분 함수적 종속 제거
```
✓ 모든 non-key 속성이 전체 PK에 함수적 종속
  - 예: GUARDIAN_MISSIONS에서 mission_id가 PK이고,
    task_description은 status_check_id에 종속되지 않음
  - 별도 테이블 분리로 해결
```

#### 제3정규형 (3NF) - 이행적 종속 제거
```
✓ non-key 속성 간 종속성 제거
  - 예: emotion_label은 diary_id에만 종속
    다른 non-key 속성에 종속 없음
  - 카테고리 정보는 별도 테이블로 관리 가능
```

### 7.2 주요 쿼리 예시

```sql
-- 임산부 임신 주차 계산
SELECT 
  FLOOR(DATEDIFF(CURDATE(), pregnancy_start_date) / 7) AS weeks_calculated
FROM PREGNANCY_INFO
WHERE user_id = ?;

-- 오늘의 상태체크 확인 (1회 제한)
SELECT * FROM PREGNANCY_STATUS_CHECKS
WHERE user_id = ? 
  AND DATE(created_at) = CURDATE()
LIMIT 1;

-- 보호자 미션 조회
SELECT m.*, s.mood, s.symptoms
FROM GUARDIAN_MISSIONS m
JOIN PREGNANCY_STATUS_CHECKS s ON m.status_check_id = s.status_check_id
WHERE m.guardian_user_id = ? 
  AND m.is_completed = FALSE
ORDER BY m.created_at DESC;

-- 임산부 일기 감정 추이 (최근 7일)
SELECT DATE(d.diary_date) AS date, 
       AVG(a.emotion_score) AS avg_emotion,
       COUNT(*) AS diary_count
FROM DIARY_LOGS d
LEFT JOIN AI_ANALYSIS_RESULTS a ON d.diary_id = a.diary_id
WHERE d.user_id = ? 
  AND d.diary_date >= DATE_SUB(CURDATE(), INTERVAL 7 DAY)
GROUP BY DATE(d.diary_date)
ORDER BY date DESC;

-- 커뮤니티 게시글 조회 (임신 시기별)
SELECT * FROM COMMUNITY_POSTS
WHERE pregnancy_period = 'MID'
ORDER BY created_at DESC
LIMIT 20;

-- 평균 가전 설정 조회 (관리자)
SELECT 
  AVG(target_temperature) AS avg_temp,
  AVG(target_humidity) AS avg_humidity,
  AVG(CAST(mood_light_brightness AS DECIMAL)) AS avg_brightness
FROM APPLIANCE_SETTINGS
WHERE DATE(created_at) = CURDATE();
```
